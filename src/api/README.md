# FastAPI REST API

This directory contains the FastAPI REST API server.

## Files

- **main.py** - FastAPI application; `routes/` holds the routers, `services/` the local execution and file services

## Endpoints

- `GET /health` - Health check
- `/api/v1/assessments/*` - The assessment lifecycle, uploads, per-phase artifacts, the assignment review and resume, schema revisions, deliverables, query journeys and the context graph (routers in `routes/`)
- `GET /api/v1/dashboard/stats` - Dashboard statistics

Experimental (#308): start the API with `MODERNIZER_EXPERIMENTAL_GRAPH_UI=1` to turn on the graph explorer, a UI page (`/analysis/explore/{job_id}`, linked from the results page) that draws a job's source tables and destination engines linked by their queries, starting from a wave, a table or an engine. Its routes (`routes/graph_explorer.py`: the probe `GET /api/v1/experimental/graph-explorer` and the bounded, read-only `GET /api/v1/assessments/{job_id}/graph/explore/` `options`, `links`, `search`, `query`, `overlays`, `below-traffic`, `query-bundles` and `walkthroughs`) are never listed at `/docs`. The probe always answers 200: `{"enabled": false}` with the flag unset or set to anything but `1` (the results page asks on every load, and then shows no entry), and `{"enabled": true, "max_links": 60, "max_options": 1000}` with it on. With the flag off, every data route answers 404 like a path that does not exist, for every method and before the job's graph is read; with it on, a path under `.../graph/explore` that is no view answers 404 and a method other than GET on one answers 405 (`Allow: GET`). The figures they return that `report.json` does not hold (bundle totals, per-table traffic, unit sizes, picker counts) are read-time aggregates of the graph, ADR-032 Decision 1's fifth family. They may change or go away when the explorer moves onto the graph query catalog (#307). `scripts/start_local_ui.py --experimental-graph-explorer` (or `make explore JOB=<job_id>`) starts the API with the flag set (and without the option, with it unset); the user guide is `docs/explore-the-graph.md`. Bounds: `options` lists at most 1,000 per kind (`limit`), `links` returns at most 60 table-to-engine bundles per expansion (`limit`, the busiest first, with the total), `search` takes 2-200 characters and returns at most 20 matches, `below-traffic` takes at most 150 query ids and 150 bundle refs, `query-bundles` at most 150 query ids (every bundle each is in, for the Questions tab's Show on graph), and the UI draws at most 150 nodes and links.

The results page's assumptions panel (#1991, `routes/assumptions.py`): `GET /api/v1/assessments/{job_id}/assumptions` lists growth and the peak with the value, origin and line the job's report states, the range the assumptions file is checked against, the phases a change re-runs and whether this server can run them (`available`, else `unavailable_reason`). `POST` takes a body in the assumptions file's form (`{"growth": 3}`), checked by the file's own parser: an unknown or collected key, a value out of range or not a finite number, a duplicate key or a body that is not one JSON object is `422`, whose detail names the field and never repeats a key or value sent. It needs `Content-Type: application/json` (`415`) and a body of at most 16 KiB, by its length or as read (`413`), and sits behind the same app-wide gate as every other write route. A change to a finished job is recorded in `decisions/assumptions.json` with origin `ui` and re-runs only synthesis (through the orchestrator's resume) and the deliverables; the result lists the phases that ran (`reran`), those skipped (`skipped`: schema design, which designs nothing without a model) and those a job the scripts made only had recorded as done (`recorded_done`). A job that is not finished, has no results, has a change running (the per-job lock `/resume` and the schema confirm routes take too, `src/orchestrator/job_lock.py`), or would need a model this server does not have (an executive summary or schema designs a model wrote) is `409` with nothing written. A failed re-run is `500`, says which phase failed, and puts the job back as it was.

`POST .../schema/confirm-all`, `.../schema/{engine}/confirm` and `.../uploads/confirm` take no body, so they also need `Content-Type: application/json` (`415`): a browser sends that type cross-origin only after a CORS preflight, which the API grants to its own UI origin alone, so a form post from another site can't reach them. The UI sends it on every call (`ApiManager`).

The graph query catalog (#307, `routes/graph.py`) asks a job's context graph the fixed, read-only questions in `src/graph/catalog.py`, the same ones `scripts/graph_query.py` asks from the command line. `GET /api/v1/assessments/{job_id}/graph/catalog` lists every entry (id, title, question, row bound, the stages it needs) with its parameters and each parameter's choices on the job's graph (at most 1,000, stated as `max_choices`; `choices_truncated` says when there are more). `POST /api/v1/assessments/{job_id}/graph/catalog/{entry_id}` runs one entry with the body `{"params": {"<name>": "<string value>"}}` and returns `columns`, `rows`, `row_count`, `truncated`, `max_rows`, a node/edge `projection`, and, when there are no rows, `unmet_needs` and an `explanation`. Neither route takes or returns Cypher. Both are always on, like the curated `GET /graph/*` views, and sit behind the same app-wide gate (loopback bind, Host allowlist, CORS for the local UI origin only, the 1 MiB body cap); they lease the job's read-only graph with the same freshness check, read timeout (`504`, 10 s per statement; a request runs its statements one after another: a list one per distinct parameter, 10 today, and a run at most 3) and read slots (`503` with `Retry-After`). At most half the handle's read slots' worth of catalog requests run at once (2 of the default 4; more get `429`), so the curated views always keep the other half. A run needs `Content-Type: application/json` (`415`) and a body of at most 64 KiB (`413`); an unknown entry is `404`, and a missing, unknown, non-string or over-1,024-character parameter, a body that is not a JSON object (too deeply nested included), or a value that is not among the parameter's choices on the job's graph (a one-row lookup, so values past the 1,000 listed choices are checked too) is `422`. All of this except the value lookup is answered before a catalog slot is taken or the graph is opened, and no error repeats the caller's names or values. Row values are returned as stored: customer text is data, and a client that renders it must escape it. The experimental graph explorer's Questions tab (`docs/explore-the-graph.md`) is a client of both routes: it lists the entries, fills each parameter from its choices, runs one, and draws the `projection`'s queries, tables and engines on the graph.

Progress is polled (`GET /api/v1/assessments/{job_id}`, `/phases`, `/execution-history`); there is no WebSocket. The running server lists every route at `/docs`, and [the high-level design, section 5](../../docs/architecture/high-level-design.md#5-api-architecture) summarises them.

## Running

```bash
uvicorn src.api.main:app --reload --port 8000
```

## Credentials are never sent (ADR-004 Decision 5)

A request names the database credentials by reference only: `connection.secret_arn` (a Secrets Manager ARN) or `connection.secret_name` (a secret name: letters, digits and `/_+=.@!-`, so RDS-managed `rds!db-...` and `rds!cluster-...` secrets work). The other forwarded fields are allowlisted too: `connection.host` is a host name or IP address (optionally `host:port`), `connection.database` a plain name, `connection.credentials_type` is `secrets-arn` or `secrets-name`, the engine, source and mode fields are plain names, and table patterns are table names and wildcards separated by commas (quote a name with spaces: `"Order Details"`, `[Order Details]` or `` `Order Details` ``). A request that carries a password, secret, token or a credential-shaped string anywhere is refused with a 400 and nothing is stored (`secret_guard.py`). Agent answers are free text, so there only a value with a credential shape is refused: an assignment of a literal (`password=...`), a quoted `PASSWORD '...'` or `IDENTIFIED BY ...`, a client flag with a value (`mysql -p<pw>`, `--password <pw>`), or user info in a connection string with a scheme, a bare host or a port. `users.password: bcrypt hash` or `token: rotates daily` is accepted. #1001 adds two forms, refused only when the value is a plain literal (the check is shared, so they also apply to the assessment routes, whose fields are allowlisted anyway) (after one pair of matching outer quotes is removed, none of `` $ { } % ` < > ( ) [ ] ! # `` and no quote, not starting with `@` or `:`, and not `?`, `...`, `***`, `xxxx`, `none`, `null`, `n/a`, `-`, a masked value (`••••••`, `…`, `REDACTED`, `**redacted**`) or a documentation word, in any case: `password`, `passwd`, `pass`, `pw`, `pwd`, `secret`, `token`, `changeme`, `change_me`, `replace_me`, `your-password`, `your_password`, `<letters, _ and ->_here` or `-here` (`YOUR_TOKEN_HERE`, `api-key-here`), `auth_string`, `new_password`, `mypassword`, `example`): a quoted literal in a `SET PASSWORD [FOR <user>] = '<pw>'` statement (or `= PASSWORD('<pw>')`), and `curl -u user:<pw>` inside one curl command (it ends at a newline, `;`, `&&`, `||`, `|`, `&`, a trailing `,` or `.`, or a word that is no flag, flag value or URL). A variable or template there (`"$user:$pass"`, `{{ .Values.pw }}`, `$(cat ~/.token)`) is not refused, and neither is a real password that contains one of those characters. Forms that may state a credential but may as well describe one are saved unchanged, with a warning in the response's `warnings` (`answers look like they contain a credential ...; use a secrets manager reference`), and the stored-file redaction never removes them: prose (`the password is <pw>`), user info before a dotted host (`admin:<pw>@db.example.com`, with or without a path), and an unquoted plain value in `SET PASSWORD FOR app = <pw>` or `CREATE|ALTER USER app PASSWORD <pw>`. Request bodies over 1 MiB get a 413 (`MODERNIZER_MAX_BODY_BYTES` overrides the limit).

Versions before #723 could store a submitted password in `artifacts/<db>/<job>/_meta.json`. When the API starts, a background thread removes any such stored credential (and any credential-shaped agent answer) once, and records `artifacts/.meta/_stored-input-redaction-v2.json` so later starts skip it (v2 since #1001 added the plain-language forms, so a v1 marker from an earlier run does not skip them). A file it cannot read or write is logged by path and skipped, the API starts regardless, and the marker is only recorded when nothing was skipped. Only credentials are removed: long values, deeply nested values and text that merely resembles a credential are kept as they are. To run it by hand, whatever the marker says:

```bash
uv run python scripts/redact_stored_inputs.py --artifact-dir ./artifacts
```

It prints the rewritten and skipped file paths (never their contents) and is safe to run more than once.

Live collection reads the secret named by either form. The API forwards `connection.secret_arn` or `connection.secret_name` as the collector's one secret id (`secret_arn` in the execution input, `SECRET_ARN` for the collector), and the collector passes it to Secrets Manager as `SecretId`, which takes an ARN or a name. When both are given, `credentials_type` picks one (`secrets-arn` or `secrets-name`); when only one is given, that one is used. A name is looked up in the collector's own account and region; a secret shared from another account needs its full ARN. The automation instance that fetches it (`infrastructure/cloudformation/automation.yaml`) may read only RDS-managed master user secrets (`rds!db-...`, `rds!cluster-...`) and secrets named `<ProjectName>/...` (`modernizer/...` by default); list any other secret's ARN in the stack's `AdditionalSecretArns` parameter (`aws cloudformation update-stack --stack-name modernizer-automation-<last 8 characters of the VPC id> --use-previous-template --capabilities CAPABILITY_NAMED_IAM --parameters ParameterKey=AdditionalSecretArns,ParameterValue=<arn>` plus `UsePreviousValue=true` for the other parameters). The API does not set that parameter: `ensure_automation_machine` (`src/tools/aws/automation.py`) never passes it, and it reuses an existing `modernizer-automation-<vpc>` stack without updating it, so a stack deployed before this change keeps reading every secret in the account until it is updated. Passing the request's own secret is part of wiring live collection end to end ([#342](https://github.com/aws-samples/sample-aws-genai-db-modernizer/issues/342)).
