# DNN Platform on SQL Server: a real application under load

`dnn.zip` holds `dnn-collection.json`, a SQL Server collection from a real application rather than a generated one: [DNN Platform](https://github.com/dnnsoftware/Dnn.Platform) 9.13.10 (formerly DotNetNuke) with the [Hotcakes Commerce](https://github.com/HotcakesCommerce/hotcakes-commerce-core) 03.12.02 store, on SQL Server 2022 (16.0.4305.5). Both applications are MIT licensed. Much of their logic lives in stored procedures, which the other samples don't have.

## How it was collected

- **Load:** 30 minutes at 100 requests a second over CMS and store journeys (browse, search, login, category and product pages, store search, cart, checkout): 176,441 requests, 0% failed, 2,567 orders placed. The database ran at about 92% CPU.
- **Collector:** `scripts/collect-sqlserver.sql` at commit 325c122, run right after the load with `@min_executions = 1`.
- **What it holds:** 234 tables, 861 stored procedures and 234 queries; the database is `DNN`.
- **Data:** all generated by the test bed's seed (500 products, 2,000 customers, 10,000 orders). There is no customer data.

## Run it

```bash
cd docs/examples/dnn && unzip -o dnn.zip && cd -
uv run python scripts/run_assessment.py --file docs/examples/dnn/dnn-collection.json --llm-mode none --all -y
```

Or in Claude Code: `/modernize docs/examples/dnn/dnn-collection.json`.

The test bed that produced it is tracked in [#1296](https://github.com/aws-samples/sample-aws-genai-db-modernizer/issues/1296).
