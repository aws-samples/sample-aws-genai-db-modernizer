# Database Modernization: Engineering Report

Source database: `app`. This is the build companion to the executive report (`executive-report.pdf`): the source-to-target mapping, the per-engine target schemas, and the query groups.

## Executive summary

Recommendation: move the app MySQL database to four AWS services in three waves. Wave 1 moves it to Aurora MySQL; wave 2 puts ElastiCache in front of 2 hot reads \(0.0% of calls\); wave 3 adds DynamoDB and DocumentDB. The projected cost of the full modernization is $200 per month at on-demand list prices. No current cost was collected for the source database, so the plan claims no saving against it.

Risk: overall risk is low, with no open risks.

Decision: approve wave 1. It is safe to approve: it moves the database 1:1 to Aurora MySQL, the same engine family as MySQL, with its current data model, and its cutover waits until schema and data parity is validated against the source.

*Engine and query assignments are produced deterministically. No language model decides which engine a table or query goes to. The executive summary is written over already-computed results and cannot change a recommendation.*

*Workload fit: how closely this engine's capabilities match the access patterns of the queries routed to it. It is not a probability that the migration will succeed.*

*Cache fit: how closely the cache layer's capabilities match the reads it fronts. The cache layer owns no queries, so this is not a workload fit and is not compared with the owning engines' figures.*
